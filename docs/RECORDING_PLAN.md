# Submission recording plan

**Target:** 105–115 seconds; hard ceiling 120 seconds. Landscape, actual hosted browser UI. Do not use recreated video UI, synthetic call states, or staged transcripts. A silent walkthrough is acceptable if the real call status and finalized evidence are legible; brief spoken narration helps explain product decisions.

## Capture route

Use macOS Screenshot or QuickTime through computer-use controls. `Command–Shift–5` opens the native recording controls. Select the browser region or screen, start recording, perform the actual app actions, then stop and save the native recording. If macOS requests Screen Recording or microphone access, the user must authorize the specific access. Do not bypass permissions or use unrelated desktop history captures.

The demo should hide the full telephone number once entered, use a clean browser viewport, and keep provider dashboards, credentials, private settings and unrelated windows outside the recorded area. Record only an authorized test participant. Capture the actual call acceptance and outcome; do not dial solely to create footage until the participant is ready.

## Shot and action sequence

| Time | Actual action | What it establishes |
| --- | --- | --- |
| 0–8s | Dashboard, briefly open the metric/trend expansion | Required dashboard exists; next action is foregrounded |
| 8–18s | Open Hot leads → Mukunda; expand buying signals; next lead | Required lead modal, intent/ICP and navigation |
| 18–28s | Calls to make: expand a row and page; Incoming callback | Ranked queue, expansion, paging and missed-call recovery |
| 28–38s | Open AI recovery; enter the consenting participant’s number; start | App triggers a real provider call; no simulated dialling |
| 38–70s | Participant answers a short price-objection roleplay | Real telephone call; actual provider states remain visible |
| 70–83s | End or let participant hang up; wait for finalized result; open review | Duration/transcript/summary come from the provider |
| 83–93s | Review prepared callback; save request; open Calendar agenda | A useful handoff with explicit time/language and unconfirmed store availability |
| 93–105s | Pulse role agents; open completed coach or ASM result; review one proposal | Live agent job and user review boundary; avoid unverified claims |
| 105–115s | Channel pinned response, send message; show repository/README link | Remaining interactions and submission handoff |

If the call takes longer, shorten screen transitions or make a transparent edit. Preserve the real outcome and disclose a shortened call where applicable. Do not speed up speech so much that the conversation becomes unintelligible. Do not claim the video demonstrates every agent if it only shows the catalogue; list other verified flows in the README.

## Suggested narration

“This is my On-Ground Call Centre assignment, built around an Indian retail associate’s next useful action. Required metrics remain available, while the queue foregrounds who needs a response and why. The lead view keeps buying signals one step away.

Here I’m starting an actual AI telephone call to a consenting demo participant. The shopper is considering a mattress and has a price objection. The app follows the provider’s real states, then waits for its finalized result.

The useful output is a request with a language, a time and an unresolved question—not an implied store booking. The associate reviews it before handing it off. Pulse keeps practice, prioritisation, calling and follow-up accessible without turning every task into another dashboard.

The README explains what is verified, what uses sample data, the trial-account limits, and where AI assisted the build.”

## Export and verification

- Save a master source recording privately.
- Export a reviewer copy as MP4, 1920×1080 or native readable landscape size, H.264 with AAC if audio exists.
- Check actual duration, inspect opening/middle/end frames, and confirm the phone number and secrets are not visible.
- Open the shared link using a non-owner session before using it in the submission email.
- A sequence of screenshots is a walkthrough artifact, not a screen recording; label it accurately if used as a fallback.
